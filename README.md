# STM32 双轮自平衡小车

基于 STM32F103C8、MPU6050 和双路编码电机的两轮平衡车固件。工程使用 STM32 标准外设库和 Keil MDK-ARM，源码已包含姿态估计、直立/速度/差速转向控制、OLED 显示、实体按键启停及蓝牙摇杆输入与调参。

**功能边界：当前没有寻迹传感器驱动、黑线位置估计或寻迹控制代码。** 本仓库公开源码与构建工程；本地 `docs/` 目录不纳入仓库。下文“已实现”仅指存在相应源码与调用链，平衡性能仍需实车测量。

> 当前状态：本地目录有一次历史 Keil 构建记录（0 error、0 warning），构建产物不会上传。本次分析没有连接硬件，也没有在本机重新编译或验证车辆稳定性。下文参数和引脚以源码为准；首次上电请架空车轮核对方向和保护逻辑。

## 硬件组成与连接

以下为**从工程配置和驱动源码反推的硬件组成**，不是经原理图核验的物料清单。仓库没有电路图、BOM、整车照片或供电接线图。采购或接线前需要核对实际板卡的电压、接口和引脚占用。

| 部件 | 源码可确认的信息 | 仍需核对 |
| --- | --- | --- |
| 主控板 | STM32F103C8，Cortex-M3；工程默认使用 72 MHz 系统时钟配置 | 实际板型、晶振、供电与下载接口 |
| 惯性测量单元 | MPU6050，软件 I²C 读取加速度与陀螺仪；初始化配置加速度 ±16 g、陀螺仪 ±2000 °/s | 模块供电/上拉电压、安装方向和机械零位 |
| 驱动轮 | 两路带增量编码器的直流减速电机；TIM3、TIM4 以编码器模式计数 | 电机型号、减速比、每转计数、轮径及左右方向 |
| 电机驱动 | 两路 PWM 加四根方向控制线，适配相应双通道 H 桥输入形式 | 驱动芯片型号、逻辑电平、电机电压、峰值电流、制动逻辑 |
| 显示器 | 0.96 英寸四线 I²C OLED 驱动，显示缓存为 128 × 64，代码发送 8 位地址 `0x78` | 实际屏幕控制器、供电与 I²C 地址配置 |
| 无线通信 | USART2，9600 bit/s，8N1，用于接收上位机的方括号文本帧 | 蓝牙模块型号、串口逻辑电平、配对与上位机程序 |
| 人机交互 | 四路低电平有效按键、PC13 状态 LED；当前仅按键 1 用于运行切换 | 物理按钮编号、LED 极性和面板标识 |
| 电源 | 源码没有电源管理或电压采样逻辑 | 电池规格、稳压器、过流/欠压保护、主控与电机共地 |

```text
                    ┌─ MPU6050（PB10/PB11 软件 I²C）
                    ├─ OLED（PB8/PB9 软件 I²C）
STM32F103C8 ────────┼─ 编码器 1/2（TIM3/TIM4）
                    ├─ 双通道电机驱动（TIM2 PWM + PB12～PB15 方向）─ 左右电机
                    ├─ 蓝牙串口（USART2）与调试串口（USART1）
                    └─ 按键与状态 LED
```

传感器、主控与驱动的**逻辑电源和地线关系必须按实物核查**；电机供电不可直接取自主控 GPIO。源码未提供电源保护设计，不能据此确定电池电压或驱动板额定电流。调试时先架空车轮，确认电机方向、编码器符号、IMU 倾角符号及停机行为，再让车轮接地。

## 快速开始

1. 用 Keil µVision 5 打开 [`Project.uvprojx`](Project.uvprojx)，目标器件为 **STM32F103C8**。工程记录使用 ARM Compiler 5.06 update 5、`Keil.STM32F1xx_DFP.2.2.0`，并定义 `USE_STDPERIPH_DRIVER`。
2. 编译后通过工程配置的调试器烧录。当前 `<CreateHexFile>` 为 `0`，若需要独立 `.hex`，先在 Keil 中启用生成 HEX 文件。
3. 核对电源、电机驱动、编码器与 MPU6050 接线。将轮子架空，观察角度和转速读数，再测试左右电机正反转与编码器符号。
4. 车辆直立并有人扶持时，用 **PB1 对应按键**启停。`RunFlag=1` 时 PC13 LED 亮；角度超过 ±50° 时当前逻辑关闭电机。初次调试应先验证停机，再逐环调 PID。

## 控制流程

```text
MPU6050 ──加速度+陀螺仪──> 互补滤波 ──角度──> 直立 PID ──┐
                                                          ├──左右 PWM──> 电机
左右编码器 ──50 ms测速──> 平均速度 ──速度 PID──> 目标角度 ──┤
                           速度差 ──转向 PID──> 差速 PWM ──┘
蓝牙摇杆 ──> 速度/转向目标；蓝牙滑块 ──> PID 参数
```

[`System/Timer.c`](System/Timer.c) 将 TIM1 更新中断配置为约 1 kHz；[`User/main.c`](User/main.c) 每 10 次中断读取 MPU6050 并更新角度与电机输出（约 100 Hz），每 50 次读取编码器并更新速度、转向环（约 20 Hz）。PWM 定时器按 72 MHz 定时器时钟配置时约为 20 kHz，占空比范围按 0–100 处理。以上频率依赖实际系统时钟为 72 MHz，尚需用示波器或逻辑分析仪确认。

角度由 `-atan2(AX, AZ)` 与 Y 轴陀螺仪积分构成互补滤波，源码中的 `Alpha=0.01`、加速度角补偿 `+0.85°`、陀螺仪原始值补偿 `+32` 都是当前样机常数，不能直接当作其他车体的标定值。编码器速度换算使用 `44`、`9.27666` 和 `0.05 s`；须确认编码器计数方式、减速比和轮径，才可给 `LeftSpeed/RightSpeed` 指定准确物理单位。PID 实现是离散式，`Ki/Kd` 参数已经隐含调用周期，更改采样周期后需要重新整定。

### 蓝牙协议（当前实现）

USART2 接受 `[` 与 `]` 包裹、英文逗号分隔的 ASCII 指令：

| 示例 | 当前行为 |
| --- | --- |
| `[slider,AngleKp,5.0]` | 修改直立环 `Kp`；同理支持 `AngleKi/Kd`、`SpeedKp/Ki/Kd`、`TurnKp/Ki/Kd`、`Offset` |
| `[joystick,0,25,25,0]` | 第二个摇杆数值 `LV/25` 设为速度目标，第三个 `RH/25` 设为转向目标 |
| `[key,...]` | 解析分支尚未实现任何动作 |

目前没有数值范围、长度、格式和超时校验。上表只用于理解现状；在修复下述 P0 问题前，不应向运行中的小车发送未知或超长数据包。

## 代码审查：不足与优化顺序

| 优先级 | 现状与影响 | 建议及验收点 |
| --- | --- | --- |
| **P0** | [`BlueSerial.c:100`](Hardware/BlueSerial.c#L100) 的接收中断向 100 字节数组写入时不检查下标；超长帧会越界。[`main.c:130`](User/main.c#L130) 对 `strtok` 返回值直接 `strcmp/atof/atoi`，缺字段会触发未定义行为。 | 接收端做长度上限、溢出丢帧与重新同步；在完整复制/锁定帧后解析；校验字段个数、数值范围和有限数。用空帧、缺字段、超长帧、非法数字验证。 |
| **P0** | [`main.c:231`](User/main.c#L231) 仅在 `|Angle|>50°` 时关停，按键仍可立即重新启动；没有 MPU6050 掉线、读数异常、控制超时和蓝牙失联的状态机。软件 I²C 的 ACK 被读取但未用于判断失败（[`MPU6050.c:7`](Hardware/MPU6050.c#L7)）。 | 建立 `DISARMED/CALIBRATING/ARMED/FALLEN/FAULT` 状态，初始化检查 `WHO_AM_I` 和每次读取结果；故障即时输出 0，回正并人工确认才重新使能；遥控超时将速度/转向目标归零。架空车轮模拟倾倒、断开 IMU/蓝牙测试。 |
| **P0** | `RunFlag`、蓝牙收包标志及 PID 目标/参数在主循环与中断之间共享（[`main.c:25`](User/main.c#L25)、[`BlueSerial.c:5`](Hardware/BlueSerial.c#L5)），缺少明确的同步协议。 | 标志使用适当 `volatile`；将整帧和多字段控制参数在临界区或双缓冲中交接，避免控制环读到更新一半的数据。 |
| **P1** | 100 Hz 控制中断里进行 14 字节软件 I²C 读取、`atan2`、浮点 PID（[`main.c:218`](User/main.c#L218)）；没有实测最坏执行时间。`TimerErrorFlag` 被置位但没有处理。 | 用 GPIO 翻转/逻辑分析仪量测执行时间与抖动；设置超时/过载诊断。若余量不足，再考虑硬件 I²C、DMA 或数据就绪触发；OLED 保持低优先级并降刷新率。 |
| **P1** | 姿态零偏为常数、`Alpha` 固定，且没有上电静止标定（[`main.c:220`](User/main.c#L220)）。MPU6050 配置为 ±16 g、±2000 °/s，当前角速度换算与后者一致，但较大的量程会降低小角速度分辨率。 | 启动后静止采样计算陀螺仪偏置与直立角零位；记录方差与温漂。按实际动态范围选择量程及 DLPF，并同步更新换算因子；通过手动缓慢倾斜验证角度符号和漂移。 |
| **P1** | [`PID.c:20`](User/PID.c#L20) 只做积分限幅，没有依据输出饱和回算或条件积分；直立环导数取相邻角度差，缺少显式 `dt`，噪声可能被放大。转向和速度指令无斜坡限制。 | 先固定周期并记录角度/角速度/PWM；再逐步加入输出饱和时冻结/回算积分、陀螺仪角速度阻尼、目标限幅和斜坡。保持调参可回退，比较超调、恢复时间与电机电流。 |
| **P1** | 速度公式中的 `44`、`9.27666` 未说明来源（[`main.c:263`](User/main.c#L263)）；电机零点、正反向和 PWM/编码器符号依赖接线。 | 把脉冲数、减速比、轮径、采样周期做成有单位的配置常量；转轮一整圈实测计数，并验证两侧前进速度同号。 |
| **P2** | 主循环每次清空并传送整个 OLED 帧缓冲，且格式化函数使用无界 `vsprintf`（[`main.c:104`](User/main.c#L104)、[`OLED.c:938`](Hardware/OLED.c#L938)）；`Serial_Printf/BlueSerial_Printf` 亦使用无界 `vsprintf`。 | OLED 限频到约 5–10 Hz，必要时只更新变化区域；格式化改用带容量上限的函数或受控格式；遥测使用有界缓冲与丢包计数。 |
| **P2** | 仍缺原理图/BOM、调参记录和故障测试；`Objects/` 内含大量可再生文件。 | 补齐硬件版本、电源/保护、驱动型号、线束、调参日志；保持构建产物不入库，拆出与硬件无关的滤波/PID/协议测试。 |

### 推荐实施路线

1. **先保安全**：修蓝牙越界与解析、实现统一停机/故障状态和遥控超时，核对电机方向。
2. **建立基线**：记录 100 Hz 内环的最坏耗时、角度/轮速/PWM/故障日志，完成 IMU 与编码器标定。
3. **改善控制**：依据日志整定直立环，再速度环、转向环；加入抗积分饱和、限速、滤波，逐项对照实测效果。
4. **整理工程**：固化引脚和硬件版本、清理构建产物、提供可复现构建与主机侧算法测试。

建议每一步至少完成：架空轮测试、扶车测试、低速地面测试，并记录相同条件下的角度峰值、稳态误差、恢复时间、控制周期抖动和故障停机反应。PID 数值不能直接照搬其他车的参数。
